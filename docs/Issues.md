# DeskBridge 问题排查

先查看两端“关于桌桥”的版本，确认一台是来源端、其余是接收端。首次配置流程见[使用 README](../README.md)。

## 无法连接

1. 来源端点击“开始共享”，确认没有其他进程占用共享端口。
2. 接收端填写来源电脑的可达 IP 或主机名；两端网络应能互通，默认端口为 TCP `24800`。
3. 检查来源端防火墙、两端端口、TLS 和兼容协议设置。
4. 检查接收端本机设备名称是否已经加入来源端布局，名称和别名应一致。
5. 查看“高级”的相关日志，区分地址不可达、连接被拒绝、设备名称和证书错误。

“逐步延长重试间隔”只影响持续失败时的重试节奏，关闭它仍会重试；“打开桌桥时自动启动共享”控制应用启动行为，两者独立。

## 已连接但不能跨屏

确认首页显示“已加密连接”和正确的相邻方向。检查来源端控制设置中的光标锁定、边缘停留、双击切屏和角落限制。Mac 检查系统的辅助功能和输入权限，修改后重新打开桌桥。Windows 发行包只用于当前用户桌面，登录屏幕及 UAC 安全桌面不在其控制范围内。

布局只读时，根据界面原因检查来源端版本、连接和文件写入权限。复杂边缘链接或外部配置需要回到来源端完整编辑器处理。

## 快捷键或输入法不符合预期

在接收端检查映射总开关、单条规则、应用范围和“应用更改”状态。确认来源习惯正确，且来源端没有冲突的全局修饰键替换。可先关闭完整适配，再逐条启用规则验证。

Mac 上远程 `Ctrl+C` 适配为 `Command+C` 会影响终端中断，包括应用内嵌终端；从范围排除终端所在应用或关闭完整适配。轻按 Shift 手势仅在 Mac 接收端合成 `Ctrl+Space`，需先在系统中设置相同的输入法切换快捷键。

## 证书提示发生变化

到对方电脑查看其本机指纹，确认设备或证书确实更新后再接受。正常升级无需主动重建证书。已有证书路径和备份说明见[配置参考](Configuration.md)。

## 提交诊断信息

向本项目[问题列表](https://github.com/shuaige619/DeskBridge/issues)报告时附上：

1. 两端“关于桌桥”中的版本、系统及构建信息。
2. 每台电脑的来源／接收角色和相邻布局。
3. 最短复现步骤、预期行为和实际行为。
4. 发生时间及相关日志片段；需要时临时开启调试日志，复现后恢复原日志级别。

分享前去掉个人地址、设备名称及其他不必要的信息。不要附证书私钥或整份用户配置；安全问题见[安全说明](Security.md)。
