# 桌桥 DeskBridge

用一套键盘和鼠标控制多台电脑，在 macOS、Windows 和 Linux 之间跨屏移动，并在接收端按应用适配快捷键。桌桥共享键鼠和剪贴板；每台电脑继续使用自己的显示器和应用。

## 下载与安装

从 [GitHub Releases](https://github.com/shuaige619/DeskBridge/releases) 下载对应系统的最新安装包和同次发布的 SHA-256 校验文件。若仓库要求登录，请使用有访问权限的 GitHub 账号。

| 系统 | 下载文件 | 安装方式 |
| --- | --- | --- |
| Apple Silicon Mac，macOS 14.4+ | `DeskBridge-版本-macos-arm64.dmg`，另有 ZIP | 打开 DMG，将 `DeskBridge.app` 拖到 `Applications` |
| Windows 11 x64 | `deskbridge-版本-win-x64-setup.exe` | 运行安装程序，默认安装到当前用户目录 |
| Windows 11 x64，便携版 | `deskbridge-版本-win-x64-portable.zip` | 解压到可写目录，双击 `DeskBridge.exe` |
| Linux x86_64 | `DeskBridge-版本-linux-x86_64.flatpak` | 用 Flatpak 安装，应用 ID 为 `local.shuai.deskbridge` |

Intel Mac、Windows ARM64 和 Linux ARM64 尚无经过验证的发行包。各平台的包和验证状态以对应 Release 为准。

**Mac 首次打开：** 当前发行包使用 ad-hoc 签名，尚未经过 Developer ID 公证。按系统提示通过“打开”或“系统设置 → 隐私与安全性”批准启动，再为桌桥授予所需的“辅助功能”和“输入监控”权限。权限变更后重新打开桌桥；更新后权限失效时也重新检查。

**Windows 首次打开：** 当前包未使用 Authenticode 签名，系统可能提示未知发布者。先核对下载来源与 SHA-256。当前发行包使用桌面进程模式，仅用于已登录的用户桌面，不接管登录屏幕或 UAC 安全桌面。

**Linux 安装：** 先安装发行版提供的 Flatpak。在只放置一个目标安装包的目录运行：

```bash
flatpak remote-add --user --if-not-exists flathub https://flathub.org/repo/flathub.flatpakrepo
flatpak install --user flathub org.kde.Platform//6.11
flatpak install --user ./DeskBridge-*-linux-x86_64.flatpak
flatpak run local.shuai.deskbridge
```

此前 Linux 版本已在 Ubuntu 22.04 X11 验证；本次安装包的具体构建与验收状态见 Release。Wayland 的输入和应用识别受桌面环境与 portal 支持限制，不能将 X11 验证结果视为 Wayland 验证结果。

## 第一次连接：以 Linux 键鼠控制 Mac 为例

准备两台网络可互通的电脑，两端安装配套版本的桌桥。将连接实体键盘和鼠标的电脑称为**来源端／服务端**，被控制的电脑称为**接收端／客户端**。一组连接中只设置一台来源端。

### 1. 在来源端添加设备并开始共享

1. 打开“设备连接 → 连接设置”，选择本机作为键鼠来源，确认本机设备名称，例如 `linux-pc`。
2. 在 Mac 的“连接设置”中查看并设置接收端名称，例如 `macbook`。设备名和别名不能与其他设备重复（忽略大小写）。
3. 回到 Linux，打开“管理设备与控制… → 设备布局”，添加名为 `macbook` 的设备，名称必须与 Mac 的本机设备名称一致。
4. 按实际摆放排列电脑。例如 Mac 放在 Linux 右边，就将 `macbook` 放在 `linux-pc` 右侧相邻格子，保存布局。
5. 在来源端点击“开始共享”。首页应显示正在共享、等待客户端。

### 2. 在接收端填写地址并核对证书

1. 在 Mac 的“连接设置”选择接收端，填写 Linux 电脑的可达 IP 地址或主机名，例如 `192.168.1.20`。不要填写 Mac 自己的地址。
2. 两端保持相同端口，默认 TCP `24800`。来源端防火墙应允许桌桥的入站连接。
3. 保持 TLS 和对端指纹验证开启，点击“连接”。首次配对时，在另一台电脑的“高级”页查看本机证书指纹，与提示中的对方指纹核对一致后再信任；按两端出现的提示完成配对。
4. 连接成功后，首页显示“已连接”及“已加密连接”，设备布局中的在线状态也会更新。

### 3. 验证跨屏与常用操作

将鼠标移到 Linux 屏幕右边缘，应进入 Mac；移到 Mac 左边缘应返回。然后依次检查：

- 在接收端输入文字，确认按键、点击和滚轮正常。
- 在两台电脑间复制、粘贴一段普通文本。剪贴板策略由来源端“管理设备与控制… → 共享行为”控制。
- 开启接收端所需的快捷键规则，在目标应用中验证复制、粘贴和输入法切换。

接收端可以是 Windows 或 Linux，来源端也可以是 Mac；配置顺序相同。来源端负责设备布局、控制热键和共享策略，各接收端负责自己的快捷键适配。

## 调整屏幕排列与控制热键

连接配套桌桥后，首页显示来源端实际配置的全部电脑。拖动电脑到空白相邻格子即可提交；也可选中后用方向键移动，按 Esc 取消。所有设备必须保持上下左右相邻连通，已占用的位置或会断开连通路径的移动会被拒绝。保存确认后各端同步布局。

新增、移除设备及设置别名，进入来源端的“管理设备与控制…”。默认网格为 5 列 × 3 行，可用设备数量受网格容量限制。外部配置、复杂边缘链接、离线或只读状态可能限制首页编辑，界面会说明原因。

“控制热键”可以切换到指定电脑、按方向切屏、锁定光标或发送按键。它在来源端执行，与接收端的“快捷键映射”分别设置。如果鼠标无法跨屏，检查是否启用了光标锁定、边缘切换延迟、双击切屏或角落限制。

## 快捷键映射

在**接收端**打开“快捷键映射”。映射仅处理另一台电脑传来的键盘输入，本机物理键盘保持原行为。

| 一键方案 | 来源习惯 | 接收端行为 |
| --- | --- | --- |
| 自动 | 由来源电脑报告系统 | 按来源与本机系统适配复制、粘贴；来源未知时先手动选择来源系统 |
| Mac 习惯 | `Command+C/V` | Windows、Linux 接收端转为 `Ctrl+C/V` |
| Windows・Linux 习惯 | `Ctrl+C/V` | Mac 接收端转为 `Command+C/V` |

相同系统习惯保持原生操作。一键方案不会改变哪台电脑提供实体键鼠。默认 Mac 规则覆盖 Codex 和飞书，可添加应用、编辑组合键，并为每条规则独立选择应用范围。

修改规则、应用范围或总开关后点击“应用更改”；规则编辑窗口保存的内容先进入草稿。一键习惯方案会直接保存并应用。在线应用设置可能短暂重连，失败时尝试恢复上次配置。关闭映射总开关仍可继续共享键鼠。

**完整快捷键适配：** 开启后按所选习惯转换更多 Ctrl／Command 组合，可限制到所选应用或用于全部应用。`Ctrl+Space` 保留，单独的修饰键和 Ctrl／Command 加鼠标点击不交换。来源端全局修饰键替换可能使接收端适配暂停，需先解除冲突。

**终端行为：** Mac 接收端将远程 `Ctrl+C` 转为 `Command+C` 后，该组合会执行复制。需要终端中断时，将终端所在应用从规则范围移除，或关闭完整适配；Codex 的内嵌终端也属于 Codex。

**轻按 Shift 切换中英文：** Mac 接收端可开启此选项并“应用更改”。远程左右 Shift 的独立轻按（不超过 300 毫秒）会补发 `Ctrl+Space`；Mac 系统必须已把该组合设为输入法切换。长按、其他按键或鼠标动作会取消手势。Windows 和 Linux 接收端保留系统原有输入法行为。

## 日常使用与升级

- “通用 → 打开桌桥时自动启动共享”控制应用启动后是否自动连接；先完成手动连接验证再开启。
- Mac 的“登录时启动”控制登录后打开应用，即时生效；需要系统批准时按界面入口完成。Windows 和 Linux 的登录启动由系统或桌面环境管理。
- 启用“关闭窗口后继续在菜单栏／系统托盘中运行”时，关闭窗口仍继续共享。要停止控制，点击“断开连接／停止共享”；要退出程序，使用菜单栏或托盘中的退出操作。
- Mac 更新前退出桌桥后替换 App，配置和证书保存在 App 外。Windows 安装版重装保留设置；便携版更新时，将旧目录的整个 `settings/` 复制到新解压目录，保留其中的 TLS 数据，避免新包的空配置覆盖旧配置。
- 安装包不包含个人连接地址、证书私钥、信任记录或运行日志。证书在本机生成；普通升级无需主动重建证书。

## 常见问题

| 现象 | 优先检查 |
| --- | --- |
| 一直连接或重试 | 来源端已开始共享；接收端地址正确；两端网络互通、端口一致，来源端防火墙允许 TCP 24800 或自定义端口 |
| 来源端拒绝设备 | 接收端本机设备名称已加入来源端布局，名称和别名设置一致 |
| 已连接但鼠标不能跨屏 | 设备相邻方向、光标锁定、角落限制和切屏条件；Mac 的辅助功能／输入权限 |
| 证书指纹改变 | 在对方电脑重新查看指纹，确认重装、证书更新或设备变更原因后，再更新信任 |
| 首页布局只读 | 两端使用配套版本，来源端在线且配置可写；复杂外部布局需在来源端完整编辑器中处理 |
| 快捷键没生效 | 在接收端配置并“应用更改”，检查总开关、逐条开关、应用范围、来源习惯与服务端修饰键冲突 |
| Shift 不能切输入法 | 仅 Mac 接收端支持；检查映射总开关及 macOS 的 `Ctrl+Space` 输入法快捷键 |
| 关闭窗口后仍在共享 | 检查“通用”中的后台运行选项；从菜单栏／托盘停止共享或退出 |

仍有问题时，从“高级”查看或复制日志，从“关于桌桥”复制版本与诊断信息；记录两端系统、设备角色、最短复现步骤和相关日志。详细步骤见[问题排查](docs/Issues.md)。
